# Assisted stylized game props — unvalidated

**Status: unvalidated.** Candidate production route for cute/stylized background props,
not a validated generator or permission to relax an existing asset's acceptance criteria.
Follow the main skill and applicable construction module. Live MCP is required for shape
authoring; headless reference analysis and optional verification helpers are not a substitute.

## 1. Agree a short work card

Apply the shared [game-asset contract](game-asset-contract.md). This concise assisted
route does not make game-first budgeting exclusive to stylized or background assets;
the same destination contract applies to all construction categories and fidelity modes.

Before geometry, fill these fields and obtain the normal scope approval. Do not create
a lengthy reconstruction brief for an approved stylized visual-guide task.

```text
Mode: stylized/gameplay read; independent or human-assisted:
Use: background/interactive; intended screen size or camera range; expected instances:
Required cues (short list):
Optional / simplified / omitted details:
Dimensions, axes; reference image and authority if measured matching is requested:
Source/materials available; protected objects/state; output folder:
Proposed delivery triangles, material slots and texture sizes:
Motion/collision needs; authorized stages (source / export / in-game verification):
First difficult-region test; shape review and delivery checks:
```

Ask about a missing decision that changes the outcome. Do not silently infer a hero
close-up budget, exact seams or permission to invent controls/rigs. A budget is an approved
proposal, not a guarantee. For a simple small static prop, a proposal around 2,000–5,000
delivery triangles and one material may be a useful starting discussion, not a universal
default or a demand to add polygons. Choose texture size from visible detail and reuse.

## 2. Build only the identifying form

Inspect the image, choose construction conditionally and prove one difficult region.
For stylized visual guides, record declared scale and facing without claiming pixel-
accurate calibration. If measured matching is requested, use the full calibrated route.

Use a modest editable cage/profile and controlled subdivision. Model silhouette,
required cavities, thickness, support contact and attachment; omit secondary wrinkles
or use texture relief only when permitted and sufficient at the intended view. Do not
build a high-resolution sculpt by habit or substitute arbitrary decimation for design.

Inspect each meaningful shape change live. During construction use cheap viewport/solid
views; at shape review capture front, side, top and three-quarter, plus a targeted
seat/contact/underside view when needed. Do not batch all renders or recompute complete
silhouette statistics after every small edit unless diagnosing measured matching.

## 3. Use human art direction as part of production

Show the actual neutral shape and name the weakest required cue. Ask for a small actionable
review such as proportions, opening size or softness, not a vague approval of unseen work.
Convert feedback into a bounded edit target and state what stays fixed. If the target is
coupled to protected geometry, diagnose the control before editing rather than promising
independence. Measure protection where affected, not arbitrary unrelated landmarks.

Distinguish normal successful construction edits, failed repairs and preference changes
in the ledger. A failed required cue remains a repair criterion regardless of wording.
Use the shared two-unchanged-failure diagnosis and six/seven failed-repair review/stop.
Further repair needs explicit bounded approval, not an endless loop or renamed checkpoint.

Human assistance is a valid outcome, not a failure of this route. Record interventions,
cost/time where available and cost to accepted delivery, not just token use or stage count.
For independent benchmarks do not coach/cross-share findings mid-run. Assisted continuation
starts a distinct lane with a newly approved brief; preserve original submissions unchanged.

## 4. Approve form, then reuse material sources

Mark only the brief's required cues present/absent/unverified with named captures. A
deliberately omitted dimple is not a blocker; a required sitting cavity still is. Obtain
shape acceptance before polish. Do not downgrade a failed required feature without approval.

Reuse supplied material sources before generating replacements. Inspect source channels,
UV scale, colour space, rights and export support. Fine weave/colour can come from the
existing texture rather than geometry. Unsupported procedural graphs still need an
approved faithful bake or simplification; a plausible new shader is not a transfer.
Material slots alone do not measure draw calls; transparency and extra passes matter.

## 5. Optimize a separate delivery copy

Preserve the editable source. Compare lower subdivision, scoped simplification or
retopology candidates at the intended screen coverage and nearest allowed view. Keep
the required silhouette, cavities, attachment and contact. Recheck topology and material/
UV ownership after conversion. A reduced mesh that closes the seat is a failure.

Record raw and evaluated source counts, delivery triangles, re-imported export vertices,
material primitives, texture dimensions and file size. UV/normal seams can split exported
vertices; never equate Blender cage vertices with runtime vertices. No universal vertex
threshold guarantees suitability. Check one prop and the intended repetition separately.

## 6. Verify and state the delivery boundary

Only run export/integration stages authorized in the work card. Existing manifest,
approval-gated export and clean-import/standalone-preview checks remain required when
shipping; this route does not bypass them or change their code. Never fabricate an
approval record to make an exporter accept an asset.

For game readiness use `gummy-game-verification` after integration approval: inspect actual
camera scale, lighting/quality, asset lifecycle, needed collision/navigation and measured
performance at representative instances. A standalone preview is format/appearance
evidence, not proof of in-game compatibility or frame time.

Report separately: editable source saved, shape accepted, budget met, export verified,
in-game verified, remaining gaps. Budget compliance or user art approval alone is not
all of those claims. Close owned verification processes and stop at the authorized boundary.
